# Academic PPT Workflow 用户使用说明书

## 1. 工作方式

系统采用固定分工：

1. GPT视觉总监提出3套艺术方向，但不负责科学事实。
2. Human选择方向、批准视觉brief、处理科学不确定性并完成最终视觉审核。
3. Codex Production OS读取获批合同和项目资料，完成证据绑定、叙事、图表、PPTX、QA和增量更新。

仓库是唯一生产权威。GPT建议、参考模板和视觉资产都不能替代输入资料中的科学证据。

## 2. 先选择正确路线

| 任务 | route | 默认视觉行为 |
| --- | --- | --- |
| 从资料生成新科研Deck | `generate` | 重大设计前先走GPT视觉总监和Human Gate |
| 已有PPT小改或增加1–10页 | `enhance` | 自动继承原Deck，不要求新视觉brief |
| 正式机构模板填充 | `template-fill` | 模板Master/Layout/品牌优先 |
| 创建可复用模板配置 | `template-create` | 仅分析获授权参考，并需人工批准 |

质量等级：

| quality | 适用场景 | 主要交付 |
| --- | --- | --- |
| `quick` | 低风险草稿、小范围增量 | Draft及受影响页面QA |
| `validated` | 日常正式制作 | PPTX、PDF、contact sheet、最小科学/视觉审计 |
| `full` | 首次高风险项目、版本冻结、最终深度验证 | 完整验证与人工交付Gate |

用户不需要准备或管理内部规划对象、缓存标识或恢复检查点。

## 3. 项目目录

所有项目位于：

```text
<PPT_WORKSPACE_HOME>/projects/<project_id>/
├─ input/
│  ├─ documents/
│  ├─ data/
│  ├─ figures/
│  ├─ references/
│  ├─ style_reference/
│  ├─ template/
│  └─ existing/
├─ brief/
├─ approved_assets/
├─ output/
├─ audit/
├─ cache/
└─ private/
```

`input/`中的正式资料视为只读。进入工作流的临床资料应先按授权要求去标识化，并启用`clinical_private`。`private/`只用于人工控制的本地材料或审批记录，工作流默认不自动摄取其中内容；不要把它当成绕过来源登记的输入目录。

创建项目：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/new_project.ps1 `
  -ProjectId "project-001" -Route generate -Quality validated
```

允许的项目ID为1–80个字母、数字、点、下划线或连字符。脚本拒绝覆盖同名项目；确需补齐缺失脚手架时才使用`-AllowExisting`。

## 4. presentation_brief.yaml

这是用户必须维护的内容合同。至少确认：

- `project_name`、演示场景、目标和受众；
- `route`与`quality`；
- 语言、时长、目标页数；
- `must_include`：必须出现的科学组件；
- `must_not_claim`：证据不允许支持的表述；
- 隐私规则；
- 正式模板或既有Deck的项目相对路径。

资料缺失时填写`INFORMATION_REQUIRED`，不得用推测补齐。正式路径使用项目相对路径，便于多设备迁移。

## 5. visual_brief.yaml与Human Gate

视觉brief只承载艺术方向，不写入研究事实、样本量、效应量、P值或结论。视觉优先级固定为：

```text
用户明确指令 > 已批准visual_brief > 获授权模板 > 既有Deck风格 > Canonical Workspace > 自动选择
```

有两项特殊规则：

- `template-fill`：正式模板的Master、Layout、Logo、机构字体和标准色属于强制品牌规则，优先于视觉brief。
- 小范围`enhance`：未要求重设计时，既有Deck自动成为默认风格，不需要GPT重新给方案。

初始化脚本可能创建`brief/visual_brief.DRAFT.yaml`。它仅用于讨论，生产不会读取。Human批准后，才另存为`brief/visual_brief.yaml`。未批准或不存在时，系统按上述优先级回退。

## 6. GPT视觉总监的使用

将演示场景、受众、获授权风格参考和可公开的非敏感摘要交给 [GPT_Art_Director.md](../prompts/GPT_Art_Director.md)。GPT应输出3套可区分方向，并说明取舍。Human选择一套或要求合并修改，最终批准视觉brief。

不要要求GPT生成或替代：

- 真实科研数据图；
- 患者影像、ECG、超声或病理证据；
- 未经输入来源支持的数字、结果或机制结论。

对于受限制材料，只在获授权的本地环境处理，不上传第三方服务。

## 7. approved_assets

该目录只接收用户已批准的非数据型视觉资产，例如背景、章节纹样或概念性装饰。把文件复制进目录并不代表批准；还必须在`approved_assets/asset_registry.yaml`登记：

```yaml
- asset_id: section-wave-01
  file: section-wave-01.svg
  role: divider_motif
  source: user_approved_generated
  scientific_evidence: false
  approved_by: reviewer-name
  approved_at: 2026-08-12
```

`scientific_evidence`必须为`false`。任何患者影像或真实科研图都应放入`input/figures/`并走来源绑定，不得放在这里。

## 8. 四条日常流程

### Generate

1. 建立项目并放入文档、数据、图和参考文献。
2. 填写内容brief。
3. 如需独立视觉方向，执行GPT视觉总监流程并批准视觉brief。
4. 运行项目，审阅contact sheet、科学审计和PPTX。

### Enhance

1. 将原PPT放在`input/existing/`，新增资料放入相应输入目录。
2. 在内容brief中写清增加/替换范围。
3. 默认不建立视觉brief，沿用原PPT的Master、Layout与风格。
4. 先审阅变化页面，再做最终交付检查。

### Template-fill

1. 将正式PPTX/POTX放入`input/template/`。
2. 在内容brief中登记模板路径和填充目的。
3. 视觉建议只能作用于模板允许的自由区间。
4. 交付前检查Logo比例、字体、页脚、页码、Master/Layout和动画保留情况。

### Template-create

1. 只放入获授权风格参考。
2. 仅提取设计规则，不复制敏感正文或未经授权图片。
3. Human批准后再用于生产项目。

## 9. 运行与输出

推荐入口：

```powershell
python run_ppt_workflow.py --project "<项目完整路径>"
```

可用`--route`和`--quality`临时覆盖内容brief，但不建议让命令行和brief长期不一致。

每次运行写入新的：

```text
output/<run_id>/draft/
output/<run_id>/final/
output/<run_id>/preview/
audit/<run_id>/
```

原始输入和既有正式输出不会被覆盖。`validated/full`的主交付至少包含PPTX、PDF、contact sheet，以及精简的科学和视觉审计。

`template-create`是配置型路线，固定交付`draft/style_profile.json`；它不会伪造Deck、PDF或contact sheet。需要成品PPT时，使用`template-fill`或`generate`。

## 10. 最终人工检查

交付前至少确认：

- 关键数字、单位、方向和不确定性与来源一致；
- `must_include`完整，`must_not_claim`未越界；
- 所有图与来源绑定正确；
- 页面可读，无严重遮挡、裁切或页脚侵入；
- 模板或既有Deck的强制风格得到保留；
- 患者和机构隐私规则满足；
- Human完成科学和视觉批准。

自动QA通过表示“可进入人工审核”，不等于最终科学批准。

## 11. 常见问题

**没有visual_brief能运行吗？**  可以。系统按模板、既有Deck、Workspace和自动策略回退。

**Enhance为什么没有视觉草案？**  小改默认保护原Deck风格。只有明确要求重大重设计时才启动GPT视觉总监。

**视觉brief能覆盖医院模板颜色吗？**  不能。正式模板的强制品牌规则更高。

**资产已放进approved_assets但没显示？**  检查是否完成登记和人工批准，且`scientific_evidence: false`。

**资料不足怎么办？**  保留`INFORMATION_REQUIRED`并补充材料；不要要求系统推测科学事实。
